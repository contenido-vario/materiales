Para usar Astro con Node.js (modo SSR) y procesar la subida de imágenes en el servidor usando el SDK de Supabase, el enfoque recomendado es crear un endpoint de tipo API con un formulario en una página de Astro configurado para procesar métodos POST.

Paso a paso de cómo estructurarlo:

1. Requisitos e Instalación

Asegúrate de tener habilitado el modo de servidor en tu astro.config.mjs y de haber instalado la librería de [Supabase JavaScript Client](https://supabase.com/docs/guides/storage/quickstart).

npm install @supabase/supabase-js

2. Configurar el Cliente de Supabase

Crear un archivo de inicialización en src/lib/supabase.js para reutilizar el cliente:

src/lib/supabase.js

No olvides añadir tus claves SUPABASE_URL y SUPABASE_ANON_KEY en tu archivo .env.

3. Crear el EndPoint de Subida (Backend en Astro con Node)

Crea una ruta de API en src/pages/api/upload.js. Dado que estás usando Node, procesaremos los datos del formulario binario directamente en la petición [Supabase Docs](https://supabase.com/docs/guides/storage/uploads/standard-uploads):

src/pages/api/upload.js

4. El Formulario en tu Página de Astro

Crear un formulario (por ejemplo, src/pages/formulario.astro) para enviar el archivo hacia tu nuevo endpoint:

src/pages/formulario.astro

Punto clave a revisar:

Políticas RLS en Supabase: Recuerda ir al panel de Supabase Storage, seleccionar tu Bucket y asegurarte de tener las Políticas RLS que permitan la inserción (INSERT) de archivos de forma pública o autenticada Supabase Docs. Si es un bucket de pruebas, puedes habilitar el acceso público total provisionalmente para verificar que todo funciona correctamente.

Para que la aplicación acepte subidas de archivos, el bucket no solo debe existir, sino que la tabla interna de la base de datos que gestiona los archivos (storage.objects) necesita una política RLS que permita la acción INSERT.

Configuraciones estándar dependiendo del caso de uso:

Opción 1: Permitir subidas solo a usuarios autenticados (Recomendado)

Esta política permite que cualquier usuario que haya iniciado sesión en tu app pueda subir archivos.

  • Operación permitida: INSERT
  • Target roles: authenticated
  • Expresión condicional (WITH CHECK): auth.role() = 'authenticated'

Opción 2: Permitir subidas públicas (Anónimas)

Usa esta opción si estás creando un formulario público donde cualquiera pueda subir un archivo sin registrarse. Atención: Esto puede exponer tu bucket a spam si no validas las subidas en el frontend o mediante funciones.

  • Operación permitida: INSERT
  • Target roles: anon (o dejarlo para todos los roles)
  • Expresión condicional (WITH CHECK): true

Opción 3: El usuario solo puede subir archivos a su propia carpeta

Si quieres organizar el bucket creando una carpeta por usuario basada en su ID, necesitas restringir el acceso para que nadie suba archivos en carpetas ajenas. [1]

  • Operación permitida: INSERT
  • Target roles: authenticated
  • Expresión condicional (WITH CHECK):
    (bucket_id = 'nombre_de_tu_bucket'::text) AND (auth.uid() = (storage.foldername(name))[1]::uuid)

[1] Esto asume que la ruta del archivo empieza con el ID del usuario, por ejemplo: nombre_de_tu_bucket/id_del_usuario/foto.png

Cómo aplicarlo desde el Panel de Supabase

  1. Entra en el Dashboard de Supabase.
  2. Ve a la sección de Storage en el menú lateral izquierdo.
  3. Haz clic en Policies (Políticas).
  4. Busca tu Bucket y haz clic en New Policy (Nueva política).
  5. Selecciona Create a policy from scratch (Crear desde cero) para tener un control total.
  6. Dale un nombre descriptivo (ej. "Permitir subidas a usuarios autenticados").
  7. Selecciona la operación INSERT.
  8. Pega el código correspondiente en el recuadro de la condición y guarda los cambios.

Como se utiliza una tabla personalizada en la base de datos para definir los roles (por ejemplo, una tabla llamada clientes o perfiles), la política de Storage debe realizar una consulta (subquery) a esa tabla para verificar si el usuario que intenta modificar el bucket tiene el rol de administrador.
